# 算价智能体框架选型

> 结论更新（基于本地源码核实：`D:\ai_agent_project\ai_lobster` 与 `D:\ai_agent_project\openclaw`）：
> **LobsterAI / OpenClaw 路线成立**，落地为 **LobsterAI 多智能体工作流：协调者 LLM agent + 专职 agent**，工具以技能形式提供给 agent；价格的合理性由**服务端校准函数（确定性重算校验）**兜底。实现路线见下文。
>
> 多智能体结构、各 agent 输出 schema 与约束算法的详细规格见 [算价智能体技能实现规格](算价智能体技能实现规格.md)。

## 结论速览

| 候选 | 是否适合 | 说明 |
|---|---|---|
| **LobsterAI / OpenClaw（有道龙虾）** | **主推** | 原生多智能体工作流（协调者 + 专职 agent）；内置 web search 技能；开发成本低 |
| LangGraph | 备选（未来需强人机协作/可回放编排时） | 能力强，但开发与部署成本高 |
| Pydantic AI | 备选 | 结构化输出最强，但多智能体编排弱 |
| CrewAI | 备选 | 角色化上手快，但确定性控制一般、token 开销大 |
| OpenAI Agents SDK | 否 | 强绑 OpenAI 生态，本项目模型为 Qwen/DashScope |
| lobster-ai（PyPI） | 否 | 生物信息学领域专用，不可复用 |

## 本地源码核实结果（三个顾虑逐一解决）

### 顾虑一：多智能体编排是 LLM 驱动，价格怎么不失控 —— 用校准约束兜底

采用**真·多智能体编排**后，LLM 驱动编排是设计选择而非缺陷，价格的合理性由**服务端校准函数（确定性重算校验）**兜底：

- **估价 agent 自主决策**：自行选择工具（历史案例库找相似价格、web 搜索找相关信息与价格、报价包锚点）收集证据并推理建议价。
- **服务端校准函数约束边界**：收到协调者输出后重算 `baseline`/`constraint_range` 并钳制 `final`（历史价格分位、锚点偏离上限、毛利下限、绝对上下限）——任何离谱价都会被代码边界拦住。
- 参数分两层：**基准价纯函数参数可精确校准**（标注数据 → 网格搜索/收缩估计），**边界约束参数只约束区间**；agent 精度靠 prompt/eval 调优。

LobsterAI 多智能体工作流已核实支持自定义 agent（独立身份/模型/技能集/工作目录），见"已核实的源码事实"。

### 顾虑二：服务契约是消息式，怎么收口 —— 已解决

本系统调用**协调者 agent**（LobsterAI 多智能体工作流入口），并约束协调者**输出严格 JSON**（结构化输出技能 + 输出 schema），请求/响应为自定义结构化 JSON；本系统侧用 schema 校验器收口。

（OpenClaw 也有 `src/mcp/openclaw-tools-serve.ts`，可把技能暴露为 MCP 工具，作为可选增强，非本方案必需。）

### 顾虑三：校准参数/版本不是原生能力 —— 已解决

校准参数（`pricing.params.json`，只定义**边界约束**）放在配置位置（带 `version`），服务端校准函数在计算约束区间时读取；精度校准退化为 **prompt/eval 调优**（独立离线任务：读标注 → 算 MAPE/偏差/区间覆盖 → 优化 agent 提示词与约束边界 → 灰度对比）。不依赖 LobsterAI 的记忆系统。

## 落地实现结构（LobsterAI 多智能体编排）

```
本系统（报价工作台，FastAPI）              LobsterAI 多智能体服务（独立 headless）
─────────────────────────               ─────────────────────────
抽取完成 → POST /estimate（同步，300s）   协调者 pricing.orchestrator（LLM，编排）
  本系统 Celery 异步触发                    ├─ pricing.precheck      预判 agent（LLM，硬门禁）
接收结果 JSON ←────  JSON  ───────────    ├─ pricing.estimator     估价 agent（LLM，自主选工具：
schema 校验 → pricing_result 落库           │     history_price_search / package_anchor_lookup / web_search）
草案接入（默认价 / 仅参考）                ├─ pricing.review        复核 agent（LLM，sanity check）
                                           └─ 服务端校准函数（确定性重算校验：
                                               baseline/constraint_range 重算 + final 钳制）
                                          工具技能：web-search 桥接（复用）、history_price_search、package_anchor_lookup
                                          参数：pricing.params.json（两层：baseline 可精确校准 + 边界约束）
                                          传输/供给/并发：见 算价智能体传输与运维契约.md
```

多智能体工作流定义（LobsterAI 自定义 agent + 服务端校验）：

- **协调者（LLM）**：`pricing.orchestrator` 编排 预判→估价→复核，汇总建议。
- **专职 agent（LLM）**：
  - `pricing.precheck`：预判 agent，硬门禁（`NOT_DOABLE`/`PROCEED`），完全信任。
  - `pricing.estimator`：估价 agent，自主选择工具收集证据并推理建议价。
  - `pricing.review`：复核 agent，sanity check → `PASS/WARN/LOW_CONFIDENCE`。
- **校准 = 服务端确定性函数**（非 LLM）：收到协调者输出后重算 `baseline`/`constraint_range` 并钳制 `final`，代码保证"约束先于自由推理"。
- 每个 agent 独立身份/模型/技能集；`web_search` 复用 `web-search` 桥接服务；`history_price_search`/`package_anchor_lookup` 作为只读工具技能。
- 校准参数文件 `pricing.params.json`（带 `version`）：第一层 baseline 参数可精确校准，第二层边界约束。

agent 间的交接与各 agent 输出 schema 见 [算价智能体技能实现规格](算价智能体技能实现规格.md)；传输与运维见 [算价智能体传输与运维契约](算价智能体传输与运维契约.md)。

## 已核实的源码事实

- **技能目录与格式**：`SKILLs/<name>/` 下含 `SKILL.md`、`scripts/`、`server/`、`package.json`。
- **技能注册**：`SKILLs/skills.config.json`（`order` / `enabled`）。
- **技能加载/启停**：`src/main/skills/skillManager.ts`（Electron 主进程加载并自动启停技能服务）。
- **web 搜索桥接**：`SKILLs/web-search/server/`（Express + Playwright + Bing/Google，Bing 对国内更友好），可被算价技能直接复用。
- **多智能体工作流**：LobsterAI 支持自定义 agent（独立身份/模型/技能集/工作目录/启用状态），可构建协调者 + 专职 agent 编排；`SKILLs/multi-agent-orchestration/SKILL.md` 定义了 supervisor/orchestrator-worker、handoff 等模式。
- **LLM 模型**：OpenClaw 支持自定义 OpenAI-compatible 模型；agent 可直连 DashScope Qwen（与本系统 `app/services/llm_service.py` 同模式）。
- **headless 部署**：技能服务可独立用 `start-server.sh` 启动（web-search 已实现此模式）。

## 部署形态

两种跑法：

- **A. 跟随 LobsterAI 桌面端**：技能服务由 Electron 主进程自动启停（web-search 即如此）。
- **B. 独立 headless（推荐）**：直接用技能的 `start-server.sh` 启动算价技能服务（可容器化、常驻），本系统通过 HTTP 调用，只做传输与校验。

推荐 B：算价技能服务独立常驻，报价系统只调用，不依赖桌面端在线。

### HTTP 服务器部署兼容性（已核实）

把 LobsterAI 布在 HTTP 服务器上，本设计**完全兼容**——方案本就是按"独立 HTTP 外部服务"设计的，服务器部署比桌面端更贴合。

- 算价智能体：以 LobsterAI 多智能体工作流部署在服务器上（网关 headless 或容器化常驻），本系统通过 HTTP 调用协调者 agent。
- web-search 桥接：已核实 host 可配置（默认 `127.0.0.1:8923`）；浏览器启动**无显示环境自动强制 headless**（`No Linux display detected, forcing headless mode`），服务器上可正常用。
- 运维适配（非设计变更）：
  - 网络绑定 `0.0.0.0` + 反向代理 + token 鉴权；
  - 技能到 web-search、到本系统上下文 API 的地址配置化（不能硬编码 localhost）；
  - web_search 生产启用需容器化装好 Chrome 依赖；无外网环境保持 `web_search.enabled=false`（P0 默认关）；
  - 容器/进程守护（systemd/PM2/Docker）+ 复用 `/api/health` 探活。
- 设计不变量不变：API 契约（本系统 ↔ 协调者 agent）、多智能体编排、约束区间、校准参数、`status` 枚举与 `SKIPPED_UNSUPPORTED` 改回机制、本系统只做传输+校验+落库。

## 风险与注意事项

- 采用**真·多智能体编排**后，确定性弱于纯代码管线：同样输入可能因模型输出波动而推理过程不同；用"固定 agent 顺序 + 严格输出 schema + 校准约束区间"兜底。
- 校准精度依赖 **prompt/eval 调优**，需要标注数据持续积累。
- agent 技能用 **JS/TS** 实现（LobsterAI 生态）；`web_search` 依赖 Playwright + Chrome，生产需容器化处理。
- 独立 headless 部署需自行做守护/鉴权/日志。
