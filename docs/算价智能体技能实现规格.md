# 算价智能体多智能体实现规格（pricing）

> 本文是 [算价智能体设计方案](算价智能体设计方案.md) 的多智能体落地规格，说明 **LobsterAI 多智能体工作流**的 agent 结构、各 agent 输出 schema、工具技能、校准约束区间算法、边界约束参数文件，以及 prompt/eval 校准闭环。实现语言为 TypeScript/JavaScript。

## 1. 多智能体结构与交接协议

### 1.1 Agent 注册表

| Agent | 名称 | 职责 | 可调用工具/资源 |
|---|---|---|---|
| 协调者 | `pricing.orchestrator`（LLM） | 编排 预判→估价→复核，汇总建议 | 调用专职 agent，不直接调业务工具 |
| 预判 | `pricing.precheck`（LLM） | 轻量能力预判（硬门禁，完全信任） | 读测试项画像 |
| 估价 | `pricing.estimator`（LLM） | **自主选择工具**收集证据并推理建议价 | `history_price_search`、`package_anchor_lookup`、`web_search` |
| 校准 | 服务端确定性函数（非 agent） | 收到协调者输出后重算 `baseline`/`constraint_range` 并钳制 `final` | 读 `pricing.params.json` |
| 复核 | `pricing.review`（LLM） | 对建议价做 sanity check | 读建议价、锚点、历史区间 |

每个 agent 在 LobsterAI 多智能体工作流中配置：独立身份、模型、技能集、工作目录、启用状态。

### 1.2 交接协议（structured handoff）

- 协调者（LLM）编排 预判→估价→复核，agent 输出为结构化 JSON（见第 3 节 schema）。
- **代码保证在服务端边界**：收到协调者输出后，服务端重算 `baseline`/`constraint_range` 并钳制 `final`（见 §4.3），不依赖协调者内部是否跳步/改写。
- `calibration` 为服务端确定性函数（约束区间 + clamp），非 LLM。
- 服务端组装响应 JSON（第 2 节），并保留 `trace`（agent 步骤、工具调用、LLM 调用）供审计。

## 2. 服务接口定义（本系统 ↔ 协调者）

本系统调用算价服务（**协调者 LLM agent** 驱动，服务端做确定性重算校验）。**MVP 为同步 `POST /estimate` + 300s 超时**；异步 `POST /jobs` 列为 P1。传输语义、供给、鉴权、并发见 `docs/算价智能体传输与运维契约.md`。


`status` 枚举与动作：

| status | 含义 | 本系统动作 |
|---|---|---|
| `PRICED` | 估价完成 | 可作草案默认价（若 `confidence` 达标） |
| `LOW_CONFIDENCE` | 低置信度/复核异常 | 估价仍返回，不写草案默认价、标注仅参考（不升级人工） |
| `SKIPPED_UNSUPPORTED` | 预判明显不可做 | 不估价，草案标记不可做/本次不报价；可在草案手动改回，但改回后不允许 AI 估价（本系统不再调用，价格手工填写） |
| `ERROR` | 内部错误 | 记录错误，不写价格 |

**幂等**：相同 `request_id` + 相同 `config_version` → 返回相同结果（协调者入口缓存，避免重复估价）。

## 3. 各 agent 输出 schema

### ① precheck（预判 agent）

```json
{
  "result": "NOT_DOABLE" | "PROCEED",
  "reason": "历史有同类案例且信息完整，可继续估价",
  "suggested_action": "SKIP" | "PROCEED"
}
```

`PROCEED` 覆盖"基本可做"与"信息不足但可估"两种情况；信息不足只会压低置信度，不阻断流程。完全信任该结果，不送人工复核。

### ② estimator（估价 agent）

```json
{
  "proposed_unit_price": 0.0,
  "proposed_range": {"low": 0.0, "high": 0.0},
  "adjustment_factors": [
    {"type": "quantity_tier", "factor": 0.95, "reason": ""},
    {"type": "complexity", "factor": 1.05, "reason": ""}
  ],
  "reasoning": "参考相似历史成交价，结合数量阶梯调整",
  "evidence_summary": [
    {"source": "history_case" | "package_anchor" | "web", "ref": "", "note": ""}
  ],
  "confidence_inputs": {"history_count": 3, "min_similarity": 0.7, "range_width_ratio": 0.4}
}
```

工具调用约束：

- **优先** `history_price_search`（相似案例价格）；案例不足时可用 `web_search`（受 `options.allow_web_search` 与 `params.web_search.enabled` 控制）。
- `package_anchor_lookup` 作为同域标准价参考。
- agent 自主决定调用顺序与组合；协调者只记录工具调用进 `trace`。

### ③ calibration（服务端确定性函数）

```json
{
  "constraint_range": {"low": 0.0, "high": 0.0},
  "final_unit_price": 0.0,
  "final_range": {"low": 0.0, "high": 0.0},
  "confidence": 0.0,
  "applied_constraints": [
    {"rule": "history_percentile", "window": ["p25", "p75"], "ok": true, "detail": ""},
    {"rule": "anchor_deviation", "max_pct": 0.5, "ok": true, "detail": ""},
    {"rule": "margin_floor", "min_margin_pct": 0.0, "ok": true, "detail": ""},
    {"rule": "absolute_bounds", "min": 0, "max": 1000000, "ok": true, "detail": ""}
  ]
}
```

`final_unit_price = clamp(proposed_unit_price, constraint_range)` 后按舍入规则取整；`final_range` 为约束区间按舍入规则取整。该函数**不在 LLM 流内**，由服务端在收到协调者输出后重算执行（见 §4.3），是代码保证。精确调参发生在 §7 基准价参数校准轨。

### ④ review（复核 agent）

```json
{
  "result": "PASS" | "WARN" | "LOW_CONFIDENCE",
  "checks": [
    {"check": "within_history_range", "ok": true, "detail": ""},
    {"check": "anchor_deviation", "ok": true, "detail": ""},
    {"check": "margin_positive", "ok": true, "detail": ""},
    {"check": "adjustment_bounds", "ok": true, "detail": ""}
  ],
  "flags": []
}
```

`LOW_CONFIDENCE` 触发条件来自 `params.review.auto_flags`（低置信度、越界、无历史、毛利为负等）；估价仍返回，但标记仅参考、不升级人工审核。

## 4. 确定性基准价与约束区间算法

### 4.1 确定性基准价（baseline，纯函数）

`baseline(test_item, context, baseline_params)` 是**纯函数**：同输入同参数 → 结果完全一致。步骤：

1. **归一化**：历史案例金额按 `quantity_summary` 归一化为单价（`final_deal_amount` 优先，缺省用 `original_quote_amount × source_weight_penalty`）。
2. **过滤**：`similarity ≥ min_similarity` 且价格/数量有效，得到有效案例数 `n`。
3. **加权**：`w_i = sim_i^sim_power × exp(-age_days_i / half_life_days) × field_weight_i`（归一化）。
4. **聚合**：`H = 加权中位`，`R_hist = [加权 p25, p75]`。
5. **锚点混合**：存在锚点时 `baseline = w_anchor × anchor.base_price + (1-w_anchor) × H`，`w_anchor` 随 `n` 减少向 1.0 收敛（薄历史 → 更依赖锚点）；`n=0` 时 `baseline = anchor.base_price`；无锚点时 `baseline = H`。
6. **分域系数**：`baseline ×= domain_multipliers[bus_type|test_domain]`（收缩后，默认 1.0）。
7. **置信度**：由 `n`、平均相似度、区间宽度确定性合成。

### 4.2 约束区间（服务端校准函数执行）

`params` 只定义边界，算法固定：

1. **基准窗口**：`constraint_range = baseline ± tolerance`，并与历史分位窗口（若可用）取交/并；有效案例数 < `min_cases` 时按 `widen_factor_when_insufficient` 放宽。
2. **锚点收束**：存在锚点时，窗口向锚点收束，偏离不得超过 `anchor.anchor_deviation_max_pct`。
3. **毛利下限**：`final` 不得低于 `cost_price × (1 + margin.min_margin_pct)`。
4. **绝对边界**：`min_price` / `max_price`。
5. **约束区间** = 上述边界取交集；`final = clamp(proposed, 区间)` 后按 `rounding.step` 舍入。
6. **置信度**：由案例数、相似度、区间宽度合成；低于 `confidence.min_confidence_to_write_draft` 时 `action_when_low=REFERENCE_ONLY`。

### 4.3 回归边界（确定性 vs 波动）

- **快照一致**：固定输入 + 固定参数 → `baseline` 与 `constraint_range` **逐位一致**（可回归）。
- **服务端重算校验（代码保证）**：收到协调者输出后，服务端重算 `baseline`/`constraint_range` 并执行 precheck 门禁与 `final = clamp(proposed, range)`——即使协调者跳步/出带外价，最终价仍落在**确定性约束带**内；回归断言是 `final ∈ constraint_range`，不是点级一致。
- **增量价值**：`delta = proposed - baseline`；用标注数据对比 agent 与 baseline 的 MAPE，量化"agent 相对基准的增量价值"。

| 分类 | 键 | 作用 |
|---|---|---|
| 基准价聚合 | `baseline.price_source_weight`/`sim_power`/`time_half_life_days`/`percentiles` | 确定性 baseline 的聚合参数（可精确校准） |
| 锚点混合 | `baseline.anchor_base_weight`/`anchor_tolerance_pct` | baseline 与锚点的混合权重（可精确校准） |
| 分域系数 | `baseline.domain_multipliers`/`domain_min_samples`/`domain_shrinkage_k` | 修正系统性域偏差（收缩估计，可精确校准） |
| 约束区间 | `constraint_window.*` | 服务端校准函数计算约束区间的算法边界（基准价±容差/最少案例/放宽） |
| 锚点约束 | `anchor.*` | 防止偏离同域标准价 |
| 毛利下限 | `margin.*` | 防止倒挂报价 |
| 绝对边界 | `absolute_bounds` | 硬边界 |
| 舍入 | `rounding` | 价格取整 |
| 证据充分性 | `sufficiency.*` | 控制低质量估价的占比 / 触发 web / 标记仅参考 |
| 置信度 | `confidence.*` | 控制自动写草案的门槛 |
| web 预算 | `web_search.*` | 成本与合规控制 |
| 复核规则 | `review.*` | 定义"仅参考"标记的边界 |

## 6. 数据来源与归一化约定

- **历史案例价格**：`history_quote_case` 的 `final_deal_amount`（成交价）与 `original_quote_amount`（报价价）；估价 agent 参考时优先成交价。
- **单价归一化**：案例金额按 `quantity_summary`（`{quantity, unit}`）归一化为单价；测试项按 `test_item.quantity` 计算小计；单位不一致的案例标记无效。
- **币种**：统一 `CNY`；本系统保证传入金额已换算。
- **B 方式上下文 API 契约**（不预取时本系统提供只读接口）：

```http
GET /pricing/context?test_item_id=xxx&top_k=5&config_version=xxx
Authorization: Bearer <token>
```

返回 `prefetched_history` 与 `package_anchor`（结构同请求 `context`）。

## 7. 校准闭环（双轨）

### A 轨 · 基准价参数校准（确定性，可精确调）

1. **采集标注**：`pricing_annotation` 记录测试项特征 + **估价时上下文快照** + `baseline`/`proposed`/`final` vs 人工确认价/成交价（快照使 baseline 可精确重算）。
2. **数据切分**：按时间切分（训练在前、验证用最近窗口），**禁止随机打散**，防泄漏。
3. **目标**：验证集 MAPE（winsorize 5% 极端值）+ 区间覆盖率。
4. **拟合**：
   - 网格搜索全局标量（`price_source_weight`/`sim_power`/`half_life_days`/`percentiles`/`anchor_base_weight`）；
   - 收缩估计分域系数：`mult = clamp(exp(mean(log(confirmed/baseline_raw))), shrink→1.0 by n/(n+k))`，`k=domain_shrinkage_k`；样本 < `domain_min_samples` 的域用 1.0；
   - 进阶特征模型（P3）：标注量达标后拟合"特征 → log 调价系数"。
5. **验证门**：新版本 val MAPE ≤ 当前版本；分域样本量上报；区间覆盖率达标。

### B 轨 · agent prompt/eval 调优

- 根据偏差方向优化估价/预判 agent 提示词（如要求参考成交价而非报价价、数量阶梯判断、web 采信边界）。
- 约束边界（`constraint_window`/`anchor`/`margin`）可微调。

### 灰度上线

- 新参数版本 / 新提示词按报价入口比例灰度 → 对比 → 全量，评估归档形成版本演化记录。
- **agent 增量价值评估**：对比 `agent MAPE` 与 `baseline MAPE`；`estimator_mode`（`agent`/`baseline`/`hybrid`）决定是否保留 LLM agent——持续跑赢 baseline 才启用。

## 8. 实现要点与验收

- **严格输出 schema**：每个 agent 输出必须过 schema 校验，不合法则重试或报 `ERROR`。
- **服务端重算校验**：`calibration` 是服务端确定性函数，在收到协调者输出后重算 `baseline`/`constraint_range` 并钳制 `final`，任何 LLM 估价都被边界兜底（代码保证）。
- **确定性回归**：固定输入 + 固定参数版本 → `baseline` 与 `constraint_range` 逐位一致（快照一致）；`final ∈ constraint_range`（确定性约束带）；`web_search.enabled=false` 时无外部网络调用。
- **agent 增量价值回归**：记录 `delta = proposed - baseline`，用标注数据定期评估 agent 相对 baseline 的 MAPE 是否跑赢。
- **边界测试**：无历史（回退锚点）、单案例、相似度低于阈值、锚点严重偏离、毛利为负、数量超大、加急等场景各一例。
- **幂等**：协调者入口对同 `request_id` + 同 `config_version` 返回缓存结果。
- **验收**：协调者端到端返回稳定 JSON；本系统（FastAPI）调用一次并落 `pricing_run`/`pricing_result`；`status` 与 `SKIPPED_UNSUPPORTED` 改回规则正确。
