# 算价智能体设计方案

## 背景

当前系统的报价链路是：抽取测试项 → 报价包匹配 → RAG 检索与能力评估 → 人工审核 → 报价草案 → 报价确认。其中**非标测试项的定价**主要依赖审核员在人工审核阶段手工确认单价，系统没有自动估价能力。标准测试项可以直接引用标准报价包价格，而非标项的价格判断基本靠人工经验，重复劳动多、历史价格沉淀没有被利用。

本方案引入一条**算价智能体链路**：抽取完成后，标准项直接取报价包价格，非标项由算价智能体直接估价，把"参考历史案例定价"从人工经验变成可追踪、可校准的自动过程。

## 总体目标

- 抽取完成后，标准测试项直接取报价包 `base_price`，不经智能体。
- 非标测试项由算价智能体直接估价，产出建议价、价格区间、置信度和依据链。
- 估价结果可作为报价草案中非标项的**默认价**，供报价员参考，但不进入报价草案的正式确认流程。
- 算价前先跑一次轻量能力预判，作为唯一门禁；**完全信任预判结果**，只有明显不可做的项被排除，其余全部进入估价。
- **本链路跳过人工审核**：对非标项直接估价，不创建技术审核任务、不要求人工确认单价。
- 采用**多智能体编排**：协调者 agent + 专职 agent（预判/估价/校准/复核），每个 agent 独立模型与技能。
- 估价 agent **自主选择工具**（历史案例库、报价包锚点、web 搜索）收集证据并推理建议价；服务端校准函数用**规则/算法约束区间**把估价约束进边界。
- 可校准参数分两层：**基准价纯函数参数可精确校准**（标注数据 → 网格搜索/收缩估计），**边界约束参数只约束区间**；agent 精度靠 **prompt/eval 调优**。
- 智能体以**外部服务**形态存在，本系统只负责传输输入、接收估价输出，不实现智能体内部逻辑。

非目标：

- 本方案不把 AI 估价接入报价草案的正式确认/生成流程（程序上不合规，见下文业务决策）。
- 本方案跳过技术审核与人工确认价；轻量预判是"能不能做"的唯一判断，完全信任其结论。
- 本方案不实现分包成本、毛利核算等超出"非标项单价估计"范围的能力。
- 本方案不保证估价准确率，只保证结果可追踪、可校准、可回退到人工。

## 业务决策（约束）

### 1. AI 估价不进入报价草案确认流程，草案仅作参考

- AI 估价可以作为报价草案中非标项的**默认价**展示。
- 一旦报价草案采用了 AI 估价（存在任一 AI 估价明细），该草案**仅作参考**，不能走报价草案的正式确认、生成、发送流程。
- 若要形成正式报价，相关非标项必须先由人工确认价格（沿用现有技术审核/报价确认流程），并以人工确认价进入正式流程。
- 原因：AI 估价没有经过人工能力确认与合规确认，直接进正式报价不符合业务合规要求。

### 2. 算价前先跑轻量能力预判（硬门禁，完全信任）

- 每个非标测试项在进入估价前，先执行一次**轻量能力预判**，作为唯一门禁。
- 预判结果二分：
  - `明显不可做`：不估价，报价草案中标记为不可做/本次不报价。
  - 其余（基本可做、信息不足但可估）：**全部进入估价流程**。
- **可恢复出口**：被预判为 `明显不可做` 的项允许在报价草案中**手动改回**（重新参与报价），但改回后**不允许 AI 估价**——该测试项不进入算价链路，价格由报价员在草案中手工填写。
- **完全信任预判结果**：本链路跳过人工审核，预判结论不送人工复核，也不以"升级人工审核"作为兜底。
- 轻量预判只做快速判断（基于抽取信息、报价包/历史覆盖度），不做完整能力评估。

### 3. 本链路跳过人工审核

- 本算价智能体的目的是**跳过人工审核**，对抽取结果直接估价。
- 不再为这些非标项创建技术审核任务、也不再要求审核员确认单价。
- 低置信度或复核异常的估价**不升级人工**，只做"不自动写入草案默认价、标注仅参考"处理，由报价员在草案中按需调整（属报价员正常操作，非审核流程）。

## 核心设计原则

### 智能体外部化，本系统只做传输

- 智能体以独立服务部署（可用成熟智能体框架实现，框架选型见附录）。
- 本系统（报价工作台）调用智能体：提交测试项画像与上下文 → 接收估价结果。
- 通过稳定的 JSON API 契约解耦，内部实现细节对报价系统不可见。

### 真·多智能体编排，协调者 LLM + 服务端确定性校验

- **协调者是 LLM agent**：编排 预判/估价/复核 专职 agent，独立身份/模型/技能集，工具以技能形式提供（`web_search`、历史价格检索等）。
- **服务端确定性重算校验**（代码保证）：收到协调者输出后，服务端重算 `baseline` 与 `constraint_range`，执行 precheck 门禁与 `final = clamp(proposed, constraint_range)`，把"约束先于自由推理"变成输出边界的代码保证（详见 `docs/算价智能体传输与运维契约.md`）。
- 输出由服务端组装：`baseline`（确定性）、`proposed`（LLM）、`final`（钳制后）、`validation`（重算与修正痕迹）。

### 估价自主推理，校准约束边界

- **估价 agent 自主决策**：自行选择工具（历史案例库找相似价格、web 搜索找相关信息与价格、报价包锚点）收集证据并推理出建议价。
- **确定性基准价（baseline）**：同时维护一个**纯函数**计算的基准价（历史价格分位 + 锚点混合），同输入同参数结果完全一致，作为**回归基线、校准锚点、与 agent 建议价的对比基准**。
- **服务端校准函数用规则/算法约束边界**：收到协调者输出后重算 `baseline`/`constraint_range` 并钳制 `final`（基准价 ± 容差 / 历史分位窗口 / 锚点偏离上限 / 毛利下限 / 绝对上下限），防止离谱价。
- 可校准参数分两层：**基准价纯函数的参数可精确校准**（标注数据 → 网格搜索/收缩估计）；**agent 靠 prompt/eval 调优**。两者并行记录，可量化"agent 相对基准的增量价值"。

### 全程可追踪、可校准

- 每次估价记录输入画像、中间产出、最终建议价、依据链、参数版本。
- 人工确认价/成交价作为标注数据，回流校准参数版本。

## 总体流程

```
本系统（报价工作台）                         算价智能体（LobsterAI 多智能体）
───────────────                           ─────────────────────
抽取完成、报价包匹配
        │
        ├── 标准项（已匹配报价包）───────────────── 不经智能体，直接取 base_price
        │
        └── 非标项 ── 提交测试项画像 + 上下文 ──►  协调者 agent
                                                   ├─ ① 预判 agent（硬门禁）
                                                   │    明显不可做 ─► SKIPPED_UNSUPPORTED（草案标记不可做）
                                                   │    其余 ─► ② 估价 agent（自主选工具）
                                                   │              history/锚点/web → 建议价
                                                   ├─ ③ 服务端校准函数（确定性重算校验并钳制）
                                                   └─ ④ 复核 agent（sanity check）
                                          ◄──── 最终价 + 区间 + 置信度 + 依据链
                                                   （低置信度仅标注"仅参考"，不升级人工）
        │
        ▼
   估价结果落库 pricing_result（可追溯）
   报价草案：非标项默认价 = AI 估价（草案标记"仅参考"，不走确认流程）
```

## 环节详设（多智能体编排）

协调者 agent（`pricing.orchestrator`）接收测试项画像与上下文，按固定流程调用专职 agent，用结构化 JSON 交接，最后汇总返回估价结果。

### ① 预判 agent（pricing.precheck，硬门禁）

- 职责：轻量能力预判，唯一门禁，完全信任。
- 逻辑：结合标准报价包覆盖、历史案例覆盖、信息完整度，产出 `明显不可做 / 可继续` 及简短理由。
- 约束：只有 `明显不可做` 被排除（不估价、草案标记不可做），其余全部进入估价。

### ② 估价 agent（pricing.estimator，自主决策）

- 职责：**自行选择工具**收集证据并推理出建议价。
- 可用工具（以技能形式提供）：
  - `history_price_search`：检索历史案例库，返回最有价值的历史价格（`original_quote_amount`/`final_deal_amount`/`discount_rate`/`quantity_summary`/`delivery_cycle_days`/`urgent_flag`），按"定价参考价值"排序（相关性 × 成交价完整性 × 时效性）。
  - `package_anchor_lookup`：查询最相近的启用中标准报价包，取 `base_price`/`cost_price` 作锚点。
  - `web_search`：联网查测试项细节与参考价（带预算与域名白名单，生产默认关）。
- 推理输出（结构化）：建议价（`proposed_unit_price`）、建议区间（`proposed_range`）、调整因子明细（`adjustment_factors`）、依据与理由（`reasoning`/`evidence_summary`）、置信度输入（`confidence_inputs`）。

### ③ 校准（服务端确定性函数）

- 职责：**不在 LLM 流内**，由服务端在收到协调者输出后**重算 `baseline` 与 `constraint_range` 并钳制**，把"约束先于自由推理"变成输出边界的代码保证。
- 约束算法（参数只定义边界）：
  - `baseline` 由纯函数计算（历史加权中位/分位 × 锚点混合 × 分域系数，详见实现规格）；
  - 约束区间 = 基准价 ± 容差（或历史分位窗口），再与锚点偏离上限、毛利下限、绝对上下限取交集；
  - 无锚点无 `cost_price` 时毛利检查 N/A（详见实现规格）；证据不足时放宽区间。
- 产出（结构化）：基准价（`baseline`，服务端重算为准）、建议价（`proposed`，LLM）、最终价（`final_unit_price = clamp(proposed, range)`）、最终区间（`final_range`）、置信度（`confidence`）、`validation`（重算与修正痕迹）。
- 说明：`baseline` 参数可**精确校准**（标注数据 → 网格搜索/收缩估计）；agent 建议价靠 prompt/eval 调优；两者并行记录。

### ④ 复核 agent（pricing.review，可选轻量）

- 职责：对最终价做 sanity check（区间内/锚点/毛利/越界）。
- 产出：`PASS / WARN / LOW_CONFIDENCE`、checks、flags。
- `LOW_CONFIDENCE`：估价仍返回，但**不自动写入草案默认价、标注仅参考**；不升级人工审核。

## 可校准参数体系（两层）

参数分两层：**基准价纯函数参数**（可精确校准）+ **边界约束参数**（约束区间）。统一带版本号，估价结果记录所用版本。

### 第一层：基准价纯函数参数（可精确校准）

决定确定性 `baseline`，可用标注数据精确校准（见"校准闭环"）：

| 类 | 参数示例 | 校准方式 |
|---|---|---|
| 价格聚合 | `final_deal` vs `original` 权重、相似度幂、时间衰减半衰期、分位点 | 网格搜索最小化 MAPE |
| 锚点混合 | 锚点基础权重、薄历史收敛斜率、锚点容差 | 网格搜索 |
| 分域系数 | `bus_type \| test_domain` 调整系数（初始 1.0） | 收缩估计（向 1.0 收缩，防过拟合） |
| 进阶特征模型（P3） | 特征 → 调价系数（轻量回归/GBM） | 标注量达到阈值后拟合 |

### 第二层：边界约束参数（约束区间）

| 类 | 参数示例 | 作用 |
|---|---|---|
| 约束区间 | 基准价 ± 容差、证据不足放宽倍数 | 服务端校准函数约束区间的算法边界 |
| 锚点约束 | 锚点偏离上限 % | 防止偏离同域标准价 |
| 毛利下限 | 相对 `cost_price` 的最低毛利 | 防止倒挂报价 |
| 绝对边界 | 最低/最高价、舍入规则 | 硬边界 |
| 证据充分性 | 案例数阈值、检索质量阈值 → 触发 web / 标记仅参考 | 控制低质量估价的占比 |
| 置信度 | 置信度阈值 → 是否写入草案默认价 | 控制自动写草案的门槛 |
| web 预算 | 开关、每项搜索上限、域名白名单 | 成本与合规控制 |

初始阶段 `config/pricing.yml` 放默认值（与现有 `config/rag_retrieval.yml` 同模式）；参数版本表（DB）二期再上。

## 数据落库（本系统侧）

智能体外部化后，本系统仍需保存估价输入与输出，保证可追溯：

- `pricing_run`：一次估价任务（关联 `intake_id`、`workflow_job`、参数版本、智能体调用返回）。
- `pricing_result`：每个测试项——输入画像、证据包摘要、**确定性基准价（baseline）**、agent 建议价（proposed）、调整明细、最终价、区间、置信度、依据链、复核结论、flags；基准价与建议价并行记录，供回归与增量价值评估。
- `pricing_annotation`：人工确认价 / 最终成交价（标注数据来源，回流校准）。
- 预判为 `明显不可做` 的项在 `pricing_result` 落 `SKIPPED_UNSUPPORTED`，本系统侧保留"禁止 AI 估价"标记；即使草案中手动改回，该标记仍保留，不重新进入算价链路。

## 校准闭环（双轨）

校准分两轨：**基准价纯函数参数精确校准** + **agent prompt/eval 调优**。

1. **采集标注**：`pricing_annotation` 记录测试项特征 + 估价时的上下文快照 + `baseline`/`proposed`/`final` vs 人工确认价/成交价。
2. **指标评估**：MAPE、平均偏差、区间覆盖率、置信度校准；**agent 增量价值**（agent MAPE vs baseline MAPE、agent 跑赢 baseline 比例）。
3. **A 轨 · 基准价参数校准**（确定性，可精确调）：
   - 时间切分（训练在前、验证用最近窗口，禁止随机打散，防泄漏）；
   - 网格搜索全局标量（聚合权重/锚点混合）→ 收缩估计分域系数 → 进阶特征模型（标注量达标后）；
   - 验证门：新版本 val MAPE 必须 ≤ 当前版本，分域样本量上报。
4. **B 轨 · agent prompt/eval 调优**：
   - 根据偏差方向优化估价/预判 agent 提示词；
   - 约束边界（基准价容差、锚点偏离上限、毛利下限）可微调。
5. **灰度上线**：新参数版本 / 新提示词按报价入口比例灰度 → 对比 → 全量；`estimator_mode`（`agent`/`baseline`/`hybrid`）决定是否保留 LLM agent——持续跑赢 baseline 才启用。

## 与现有流程衔接

- 抽取完成后，对非标项后台异步发起算价（复用 `WorkflowService` + Celery 模式，类似现有 `rag_assess_nonstandard_items`）。
- 报价草案构建时：
  - 标准项取报价包价。
  - 非标项默认价 = AI 估价（若存在且置信度达标），草案标记"仅参考"，不走确认流程。
  - 预判为明显不可做的项：不估价，草案中标记为不可做/本次不报价；**可在草案中手动改回**，但改回后不允许 AI 估价，价格由报价员手工填写。
  - 低置信度估价：不自动写入默认价，标注仅参考。
- **本链路不创建技术审核任务、不要求人工确认价**；轻量预判是"能不能做"的唯一判断，完全信任其结论。
- 修订版链路：新增/修改的非标项复用同一算价入口重新估价。

## 外部服务 API 契约（本系统 ↔ 算价智能体）

本系统调用算价服务（**协调者 LLM agent** 驱动，服务端做确定性重算校验），契约保持结构化 JSON，详细 schema 见 `docs/算价智能体技能实现规格.md`。

**MVP 为同步 `POST /estimate` + 300s 超时；异步 `POST /jobs` 列为 P1。传输语义（超时/重试/幂等）与服务器供给/鉴权/并发隔离见 `docs/算价智能体传输与运维契约.md`——上线前必须先冻结。**

请求（本系统 → 协调者 agent）：

```json
{
  "request_id": "",
  "test_item": {
    "atomic_test_item": "",

  "context": {
    "matched_package_id": null,

```

## 落地实现路线（LobsterAI 多智能体编排）

基于对本地源码（`D:\ai_agent_project\ai_lobster` 与 `D:\ai_agent_project\openclaw`）的核实，智能体以 **LobsterAI 多智能体工作流** 落地：协调者 agent + 专职 agent，工具以技能形式提供给 agent。选型与源码证据见 `docs/算价智能体框架选型.md`。

### 结构

- **协调者（LLM）**（`pricing.orchestrator`）：本系统入口，编排 预判 → 估价 → 复核，汇总建议。
- **专职 agent（LLM）**：
  - `pricing.precheck` 预判 agent（硬门禁）；
  - `pricing.estimator` 估价 agent（自主选择工具：`history_price_search` / `package_anchor_lookup` / `web_search`，推理出建议价）；
  - `pricing.review` 复核 agent（sanity check）。
- **服务端校准函数**（非 LLM）：收到协调者输出后重算 `baseline`/`constraint_range` 并钳制 `final`（代码保证）。
- **技能（工具）**：`history_price_search`、`package_anchor_lookup`、`web_search`（复用 web-search 桥接服务）。
- 校准参数文件（`pricing.params.json`）只定义**边界约束**，带版本。
- 每个 agent 独立身份/模型/技能集（LobsterAI 多智能体工作流原生支持），agent 间以结构化 JSON 交接。

### 本系统接入

- 本系统（FastAPI）同步调用 `POST /estimate`（300s 超时，本系统 Celery 异步触发），请求体含测试项画像 + 上下文（历史案例预取 + 报价包锚点）+ 参数版本；服务端（协调者 LLM + 确定性校验）输出严格 JSON 估价。
- 本系统侧对响应做 schema 校验后落 `pricing_run` / `pricing_result`。
- 部署采用独立 headless 服务（LobsterAI 网关或技能服务常驻，可容器化），报价系统只做传输与校验。

### 分期调整

- P0 即按上述多智能体结构实现协调者 + 专职 agent + 工具技能 + 约束算法 + 参数文件 + 本系统调用与落库。

## 分期

- **P0**：多智能体编排（协调者 + 预判/估价/校准/复核 agent）+ 工具技能（历史/锚点）+ 约束区间算法 + 参数文件 + 本系统调用与落库 + 报价草案接入（默认价、仅参考标记）。
- **P1**：联网搜索按需启用 + 草案内估价卡片展示。
- **P2**：prompt/eval 校准闭环（标注采集 + 指标看板 + 提示词/约束边界版本灰度）。
- **P3**：进阶调优（可选）。

## 开发计划

两条开发线以"本系统 ↔ 协调者 agent"契约为界，**契约冻结后并行开发**：**LobsterAI 侧**（多智能体工作流，TS/Node）负责协调者 + 专职 agent 与工具技能；**本系统侧**（`ai_quote_master`，Python/FastAPI）负责触发、调用、校验、落库与草案接入。周次为单人/端估计，按团队规模等比压缩。

### A. LobsterAI 侧任务（多智能体编排）

| ID | 任务 | 交付/验收 |
|---|---|---|
| L0 | 契约与 schema（与系统侧共同冻结） | 定义请求/响应与各 agent 交接 JSON schema |
| L1 | 多智能体骨架：协调者 + 空 agent 管道 | LobsterAI 多智能体工作流跑通；协调者编排 预判→估价→校准→复核（各 agent 先返回 stub） |
| L2 | 工具技能：`history_price_search`、`package_anchor_lookup` | 历史案例价格/报价包锚点可被 agent 调用并返回结构化结果 |
| L3 | 预判 agent（`precheck`） | 硬门禁二分（`NOT_DOABLE`/`PROCEED`），完全信任 |
| L4 | 估价 agent（`estimator`，自主选工具） | 自行调用历史/锚点/web 工具，输出建议价+区间+调整因子+理由+置信度输入 |
| L5 | 服务端校准函数（`calibration`，确定性重算校验） | 服务端重算 `baseline`/`constraint_range` 并钳制 `final`；precheck 门禁；`validation` 记录；参数文件只定义边界 |
| L6 | 复核 agent（`review`） | 产出 `PASS/WARN/LOW_CONFIDENCE`，`auto_flags` 命中标记仅参考 |
| L7 | web_search 复用（P1，默认关） | 复用 web-search 桥接；参数开关控制 |
| L8 | LobsterAI 侧测试与验收 | 各 agent 输出 schema 校验；协调者端到端返回稳定 JSON；固定输入可回归 |

### B. 本系统侧任务（ai_quote_master）

| ID | 任务 | 交付/验收 |
|---|---|---|
| S0 | 契约与 schema（与技能侧共同冻结） | Pydantic 请求/响应模型 + 校验器 |
| S1 | 数据表迁移：`pricing_run` / `pricing_result` / `pricing_annotation` | Alembic 迁移通过 |
| S2 | 算价客户端 + 响应校验 | 调用 `POST /estimate`，响应过 schema 校验后落库 |
| S3 | 异步触发：抽取完成后发起算价 | Celery/`WorkflowService` 任务（仿 `rag_assess_nonstandard_items`） |
| S4 | 预取上下文：历史案例 Top-K + 报价包锚点 | 复用现有 RAG 检索，组装请求 `context`（方式 A） |
| S5 | 报价草案接入 | 非标默认价 = AI 估价（置信度达标）+ 草案"仅参考"；`SKIPPED_UNSUPPORTED` → 标记不可做 + 手动改回但禁止 AI 估价；低置信度 → 仅参考不写默认价 |
| S6 | 影子验证 | 算价 vs 人工确认价比对（MAPE/偏差/区间覆盖），产出报告 |
| S7 | 灰度启用 | 按报价入口比例写草案默认价 |
| S8 | 校准闭环（P2） | 标注采集、指标看板、参数版本灰度 |

### 里程碑排期（两端并行）

| 里程碑 | 周次 | LobsterAI 侧 | 系统侧 | 验收 |
|---|---|---|---|---|
| M0 契约冻结 | W1 | L0 | S0 | 两边 schema 校验桩通过，契约定稿 |
| M1 骨架+工具 | W2–W3 | L1、L2 | S1、S2 | 协调者编排跑通（stub）；历史/锚点工具可用；系统侧落库 |
| M2 预判+估价 | W4–W5 | L3、L4 | S3、S4 | 预判硬门禁 + 估价 agent 自主工具推理出建议价→落库 |
| M3 校准+草案 | W6 | L5、L6 | S5 | 服务端校准函数（重算校验+钳制）生效；草案默认价/仅参考/`SKIPPED_UNSUPPORTED` 改回逻辑正确 |
| M4 联调+影子 | W7 | L7、L8 | S6（共同） | 影子验证报告（MAPE/偏差/区间覆盖） |
| M5 灰度+调优 | W8 | — | S7、S8 | 按入口灰度启用；prompt/eval 调优启动 |

### 依赖与并行要点

- **契约先行**：M0 是两端并行前提，契约未定不动工。
- **约束先于自由推理**：L5 服务端校准函数先于 L4 估价/协调者 agent，保证任何 LLM 估价都被确定性边界兜底。
- **两端并行窗口**：M0 冻结后，LobsterAI 侧重 L1–L6，系统侧重 S1–S5，可并行；M4 汇合联调。
- **影子验证先于启用**：M4 用真实数据证明准确度，M5 才写草案默认价。
- **后置项**：L7（web_search）与 S8（prompt/eval 调优）不阻塞主链路启用。
