# Quote Master 本地工作流

这是唯一的入口 Skill。不要把两个阶段的提示词全部内联到对话中；按实际输入读取对应参考文件：

| 阶段 | 读取文件 | 触发条件 |
| --- | --- | --- |
| 客户文档抽取 | `references/customer-extraction.md` | 总是先执行 |
| 标准规范/测试用例 | `references/standard-spec.md` | 输入包含标准、测试方法、技术要求或测试规程 |

读取本 Skill 后，使用 Read 工具读取需要的参考文件；相对路径以本文件所在目录为基准。没有触发条件的阶段不要读取或执行。

## 本地边界

- 不调用旧的 Quote Master HTTP API、`quote_master.mjs`、`QUOTE_MASTER_BASE_URL`、任何 `/api` 端点、外部登录或远程任务。
- 直接读取用户附件，复用现有 `pdf`、`docx`、`xlsx` 技能做本地转换。
- 先生成工作区内的报价草稿；用户明确确认后才导出正式 XLSX/DOCX/PDF。

## 文件转换

1. 从用户消息或附件元数据取得确切文件路径，绝不凭空编造路径。
2. PDF 优先使用 `pdftotext -layout`；扫描件或文本不完整时使用 `pdf` 技能的页面渲染/OCR。
3. DOCX 使用 `pandoc --track-changes=all input.docx -o output.md`（可用时），否则使用 `docx` 技能。
4. XLSX 使用 `xlsx` 技能或只读转换为 CSV/JSON，不修改原始工作簿。
5. 转换后的 Markdown 必须保留来源信息：

```md
<!-- source_file_name: example.pdf -->
<!-- page: 3 -->
# Source: example.pdf
```

表格尽量保留 `<!-- sheet: Sheet1 row: 12 -->`。标题、表格、页码和 sheet 元数据都是证据定位的一部分。

## 大文件和合并

- 按章节、页或表格分块；默认每块不超过约 40,000 个字符，保留约 1,000 个字符重叠。
- 模型返回截断或非法 JSON 时，将对应块减半重试。
- 合并分块结果时，以总线、父级路径、名称或测试编号为候选键；只合并同一事实。
- 相同 item 合并 evidence 和 testcase，并去除完全重复的 testcase；平台、协议、端口、样件、环境、数量、轮次或标准不同都保留为变体。

## 抽取后校验

- 每个 item 必须有 `temp_id`、原文名称和至少一条能在转换后 Markdown 中找到的短 evidence；找不到时降低 confidence 并加入 warnings。
- 不把目录重复、普通步骤、报告格式、评审会议、日报周报和过程沟通误报为测试项。
- `category_path` 只放父级；标准规范里的子用例留在 `testcases`，不得抬成 item。
- 标准、价格、周期、数量和客户信息都必须有文档证据；缺失就留空或列入 `missing_information`。
- 先区分 `已确认`、`推断`、`待确认`；不确定项必须标记人工复核。

## 报价草稿

在当前工作区写入 `quote-draft.md`（或用户指定的草稿路径），至少包含：

- 文档和客户范围摘要；
- 测试项明细（编号、名称、父级、总线/域、数量、标准和证据位置）；
- 低/基准/高三档人日或工时，以及准备、环境、执行、分析、报告和复测/缓冲假设；
- 有依据的价格或价格区间；没有依据时写“待确认”；
- 交付物、周期、前提条件和除外事项；
- 缺失信息、客户确认问题、证据覆盖率、warnings 和人工复核项。

不得编造测试项、标准、价格、周期、数量、客户信息、实验室能力或处理状态。未经用户确认，不得发送、覆盖任何正式报价文件，也不得声称报价已批准。
